Bug_Track — event detection for field-biology videos

A video-analysis tool built for a biology field experiment: it finds the timestamps of predation events automatically.

GITHUB ↗

Motivation

In my second year of high school, a friend in the biology program was running a field experiment: whether spider webs of different shapes differ in predation efficiency. The method was to record webs with field cameras over long periods, then log every predation event and its timestamp by hand.

That workflow had three problems. Outdoor lighting shifts hard and the background is noisy, so image quality is unstable. Labeled insect samples were too few to build a supervised dataset, which ruled out trainable detectors like YOLO. And manual annotation is slow; with observer fatigue and subjective judgment differing between members, the logged results were often inconsistent, which weakened the data.

System design

Long videos are first split into fixed-length segments with FFmpeg and decoded segment by segment, so memory use does not grow with video length. Each segment is scored frame by frame for change, with the detector implemented as a pluggable module — ten methods in total: dense and sparse optical flow, ORB feature matching, frame differencing, histogram differencing, motion contours, block-based local differencing, edge-change detection, a small-object flow variant, and temporal differencing over a frame buffer. Different shooting conditions — lighting drift, target size, movement speed — call for different methods, so the choice is a runtime parameter rather than a rewrite.

The output is a time series of change scores. Segments above the detection threshold are flagged as candidate events, consecutive above-threshold frames are merged into one event span, and the results are rendered as charts plus a JSON export for downstream statistics.

The PyQt5 interface exposes the pipeline parameters — video and output paths, segment length, detection threshold, analysis method — and shows slicing and chart-generation progress, so researchers without a CS background run the analysis themselves.

Outcome

Manual annotation time dropped sharply, results no longer varied by observer, and the data became more reliable. The code is public on GitHub.
